# Hero TV model

The 3D TV in the hero (`public/models/tv.glb` and its baked shading, `public/models/tv-ao.webp`)
is generated by these scripts in Blender 5.2. Edit the numbers in `build_tv.py` and re-run
rather than editing the model by hand.

| Script | What it does |
| --- | --- |
| `build_tv.py` | Builds the TV in a `Module01_TV` scene: shells, screen, trim, base and I/O parts, grouped under empties named after the explode parts in `src/components/tv/parts.ts` |
| `preview_setup.py` | Optional. Adds a lavender studio, softboxes and a camera in a separate `Preview` collection for test renders |
| `bake_export.py` | Unwraps a shared `AO` UV map, bakes ambient occlusion with Cycles, and exports the Draco-compressed GLB to `public/models` |

Run them in order from Blender's Python console, passing `__file__` so paths resolve from the repo:

```python
for name in ("build_tv.py", "preview_setup.py", "bake_export.py"):
    path = rf"D:\Repos\franco-roura\tools\blender\{name}"
    exec(compile(open(path, encoding="utf-8").read(), path, "exec"), {"__file__": path})
```

The bake is smoothed slightly before saving (raw bake noise doesn't compress), which keeps the
AO WebP around 33 KB. Re-running the UV step changes the atlas layout, so always bake and export
together: a GLB and AO file from different runs won't line up.

Material names (`M1_Shell`, `M1_Satin`, `M1_Charcoal`, `M1_Signal`, `M1_Rubber`, `M1_Metal`,
`M1_LED`, `M1_Glass`, `M1_Screen`) are how the site swaps in its own materials, so keep them.
The screen's photo or Rive texture goes on the `screen_display` mesh.
